UnraidClaw 0.1.38 lets an agent change an installed container's settings and rebuild it the way the Docker tab does, clean up unused Docker images and see which containers have an update waiting. It also closes gaps where install plans and update previews could show a secret, and where a device could pass all of `/dev` to a container. There are 60 tools, up from 55.

## Highlights

### Container settings

- `GET /api/template/:name` and `unraid_template_get` read an installed container's saved template: image, network, fixed IP, privileged mode, Extra Parameters, Post Arguments, CPU pinning, memory limit, Tailscale, and every port, path, variable, label and device. Masked and secret-named values come back as `***`.
- `POST /api/template/:name/edit` and `unraid_template_edit` change the template and rebuild the container from it. Unraid's own docker manager builds the command, so every setting the Docker tab supports works the same way, including the privileged mode, devices and custom networks that app updates refuse.
- The replacement is created before the running app is touched and must still be running a few seconds after it starts. Otherwise the original comes back, its template is unchanged, and the error carries the new container's last log lines. The template is backed up to `/boot/config/plugins/unraidclaw/template-backups/` and saved only once the rebuilt container checks out.
- `"pull": true` pulls the newest image for the tag first, so it also updates containers `unraid_ca_update` refuses. App update refusals now point to it.
- `dryRun: true` shows the changes and the exact command without pulling, creating or writing anything. See [Container settings in the README](https://github.com/emaspa/unraidclaw#container-settings).

### Docker images and update status

- `GET /api/docker/images` and `unraid_docker_images` list every image with the containers, running or stopped, that use it, and flag dangling and unused images with byte totals. The listing includes the untagged image an update pull leaves behind under Docker 29's containerd image store, which a plain `docker image ls` hides.
- `POST /api/docker/images/prune` and `unraid_docker_prune_images` remove images no container references: untagged ones by default, or every unused one with `"mode": "unused"`, optionally only those older than `olderThanHours`. Each image is removed by ID with `docker rmi`, without force, and a fresh listing verifies the result. It needs `docker:delete`.
- `GET /api/docker/updates` and `unraid_docker_update_status` report which containers have an image update, from the cache Unraid's own update check writes, with the cache's age. Nothing is pulled and no registry is contacted. See [Docker images](https://github.com/emaspa/unraidclaw#docker-images) and [Container updates](https://github.com/emaspa/unraidclaw#container-updates).

## Security and reliability fixes

- Install plans, update previews and their error messages no longer show secrets the template leaves unmasked. A variable or label is treated as secret when a word of its name ends in `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD`, `PASS`, `PWD`, `KEY`, `AUTH` or `CREDENTIAL(S)`, so `TUNNEL_TOKEN`, `WEBPASSWORD` and `apiKey` are hidden while `KEYBOARD_LAYOUT` and `MAX_TOKENS` are not. Install plans previously hid nothing, including masked template defaults, and install errors could quote the docker command Unraid ran. Docker and the template on flash still get the real values.
- `POST /api/docker/containers` and `unraid_docker_create` refuse a device such as `/dev/.` or `/dev//`, which docker reads as every device under `/dev`. Each part of a device path must name something.
- An edit that sets Extra Parameters or Post Arguments accepts only letters, digits, `: . , / + = _ -` and single spaces, as docker create does, because Unraid hands both to the shell unescaped.

## Other changes

- The OpenClaw plugin is 0.1.18 on npm, with the five new tools and guidance for them in `SKILL.md`. The CLI reads the same tool definitions, so it gains `template get`, `template edit`, `docker images`, `docker prune-images` and `docker update-status`.

## Upgrade notes

- The new permissions `template:read` and `template:update` are off after upgrading. `template:read` is part of the **Read-Only** preset. `template:update` is in no preset but full admin: privileged mode and host devices give a container the host, so grant it as you would root access.
- `docker:read` now also covers listing images and update status, and `docker:delete` also covers pruning images.
- A `devices` entry such as `/dev/.` or `/dev//` that `POST /api/docker/containers` used to accept is now rejected with `400`.
